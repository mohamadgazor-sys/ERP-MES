# SQLite Persistence Mapping and Initial Migration (demonstration scope)

| | |
|---|---|
| **Status** | Implemented for review in the initial-migration pull request. |
| **Scope** | The approved initial subset: customer, request, request item, item stage and QC approval. Nothing else is mapped. |
| **Basis** | Domain and Database Specification sections 2, 4, 5, 6, 25, 26; Decision Log #23-#25, #31, #55, #56, #58; `docs/DOMAIN_MODEL_DEMO_SCOPE.md`. |
| **Not decided here** | The production database provider and version (SQL Server stays undecided); seed data and reset (next PR); any new business rule. |

## 1. Where things live

| Piece | Project | Why |
|---|---|---|
| `ErpMesDbContext`, entity configurations, UTC converter | `ERP.MES.Infrastructure` (`Persistence/`) | Provider-neutral model (EF Core Relational only). Business rules stay in the Domain; the configurations only say how the Domain types are stored. |
| `SqliteDatabase` (connection options, `MigrateAsync`), the migrations and the model snapshot | `ERP.MES.Infrastructure.Sqlite` (`Migrations/`) | One migration set per provider (approved convention). |
| `ErpMesDbContextFactory` (design-time) | `ERP.MES.Provisioning` | The `dotnet-ef` startup project; the tool did not discover the factory in the migrations library. |

The Domain types are mapped as they are: constructors, private setters and backing fields are used by EF Core; no Domain type was changed and no Domain rule is repeated as a database check constraint.

## 2. What is stored

| Table | Notes |
|---|---|
| `Customers` | Name, active flag, audit fields. |
| `Requests` | `RequestNo` stored exactly with the `BINARY` collation (case-sensitive); unique index on (`CustomerId`, `RequestNo`, `JalaliRequestYear`) (spec 4.2, 26). `Status` is stored as the enum's integer value. |
| `RequestItems` | `ItemNo` with `BINARY` collation; unique index on (`RequestId`, `ItemNo`) (spec 5.2). Planning `Priority` lives here and is inherited by stages (Decision Log #58). Quantities are exact decimals stored as text; no precision is set because the scale is open for Milestone 2. |
| `ItemStages` | Surrogate key; unique index on (`RequestItemId`, `StageNo`). `PlannedTotalMinutes` is derived and not stored. No priority column. |
| `QcApprovals` | The demo-only approval record (one approved quantity). It does not represent accepted/rework/scrap dispositions (a production requirement). |

Foreign keys: `Requests` to `Customers`, `RequestItems` to `Requests`, `ItemStages` and `QcApprovals` to `RequestItems`. **All use restrict**: transactional rows are not physically deleted (spec 25.3). Foreign keys are enforced on every connection. Timestamps are UTC text; values read back are marked as UTC by a converter (SQLite returns an unspecified kind and the Domain requires UTC). Dates are `DateOnly` text.

## 3. The migration

`InitialCreate` was generated by the pinned `dotnet-ef` 10.0.13 on the Windows CI runner (SDK 10.0.401), because the SDK is not available in the authoring environment. A temporary workflow printed the generated files as base64 with their SHA-256; they were decoded here, the hashes checked, and the actual generated files committed unchanged (including their line endings and byte-order marks). The temporary workflow is not part of the pull request. Command:

```text
dotnet ef migrations add InitialCreate --project src/ERP.MES.Infrastructure.Sqlite --startup-project src/ERP.MES.Provisioning --context ErpMesDbContext --output-dir Migrations
```

The first generation attempt built successfully but reported "No DbContext named 'ErpMesDbContext' was found", because the design-time factory sat in the migrations library; moving it to the startup project fixed this.

The schema is created only by applying this migration (`SqliteDatabase.MigrateAsync`). Opening a database that is already up to date applies nothing. `EnsureCreated` is not used anywhere (a test scans the source).

## 4. Limitations and open mapping questions

| # | Question | What the code does meanwhile |
|---|---|---|
| M1 | Request status, work type and priority are enum integers; the specification mentions controlled status records/codes (reference tables). | Integers; no reference tables. |
| M2 | Decimal columns are SQLite text; numeric comparison in SQL (sorting, sums) is not reliable on text. | Exact values round-trip; business queries must not rely on SQL decimal ordering (Decision Log #25). |
| M3 | `ItemStages` and `QcApprovals` have surrogate keys the Domain does not expose. | Shadow keys; the Domain has no stage or approval identity yet. |
| M4 | The Domain has no optimistic-concurrency version (`Version` column approved in the persistence conventions). | Not mapped; added with the Domain support for it. |
| M5 | Indexes beyond the unique business keys and foreign keys (for example by request date or status). | None; to be decided from real queries. |
| M6 | No audit table and no workflow history are mapped. | Out of this subset. |
| M7 | Behaviour on SQL Server (collation, decimal precision, `DateOnly`) is not verified. | The model is provider-neutral, but only SQLite is tested. |
