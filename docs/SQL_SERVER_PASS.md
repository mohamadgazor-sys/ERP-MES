## 1. What was found while preparing it

1. **`UseCollation("BINARY")` is SQLite-only.** Ten shared configurations ask for the SQLite collation to make business keys case-sensitive (customer request number, usernames, codes, document references). SQL Server has no such collation and its default is case-insensitive, which would silently break the rule "RequestNo comparison is case-sensitive" (Decision Log #1, #31). `ErpMesDbContext.OnModelCreating` now replaces `BINARY` with `Latin1_General_100_BIN2` when the provider is SQL Server; SQLite is unchanged (all existing tests).
2. The rest of the shared code is provider-neutral: no raw SQL, no SQLite function, no provider type in the Application or Infrastructure projects. Filtered unique indexes (`[EndedAtUtc] IS NULL`, used to make the database refuse a double-booked machine or operator) use syntax both providers accept.
3. Open for the owner/IT: which SQL Server edition and instance, its default collation, backup and connection-string handling (never in Git), and when the provider package is approved for production (Decision Log #117 records it as used by tests only).

## 3. Reproducible path on a machine with network access

```
docker run -d --name mssql -e ACCEPT_EULA=Y -e "MSSQL_SA_PASSWORD=<strong password, not committed>" -p 1433:1433 mcr.microsoft.com/mssql/server:2022-latest
export ERPMES_SQLSERVER="Server=localhost,1433;User Id=sa;Password=<same>;TrustServerCertificate=True;Encrypt=True"
dotnet test tests/ERP.MES.Infrastructure.SqlServer.Tests/ERP.MES.Infrastructure.SqlServer.Tests.csproj
```

Generating a further SQL Server migration (the initial one is committed). Without local package access, run the workflow `SQL Server integration` manually (`workflow_dispatch`): its `generate-migrations` job prints the files between `BEGIN_MIGRATIONS_B64` and `END_MIGRATIONS_B64` (tar.gz, base64) to commit. Locally:

```
dotnet ef migrations add InitialSqlServer --project src/ERP.MES.Infrastructure.SqlServer --startup-project src/ERP.MES.Infrastructure.SqlServer.Design --context ErpMesDbContext --output-dir Migrations
```

## 4. If the sandbox should run it

The cloud environment's network policy must allow `api.nuget.org` (package restore) and `mcr.microsoft.com` (the SQL Server image), and Docker must be able to run the container. The steps are in the environment's settings (Network access).
